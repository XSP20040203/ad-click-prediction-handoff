# AUC 优化方案

更新时间：2026-10-28。

本文整理当前已验证结果及后续实验顺序。后续方向均为待验证假设，不代表已经取得提升，也不承诺 AUC 一定达到 0.8 或 0.85。

## 1. 优化目标

在原始数据基础上，提升对已有用户新广告记录的点击排序能力。主流程保持每一天都有数据参与训练，在相同验证划分上比较方案，并通过额外划分确认结果。

当前应优先补充“用户喜欢什么广告”的匹配信息。学习率、网络层数、dropout 和模型融合放在有效输入与交互得到验证之后。

阶段目标：

1. 稳定超过当前基线 AUC **0.730185**。
2. 优先寻找同一验证口径下约 **0.003～0.005** 或更大的可重复增益。
3. 在此基础上探索 0.74 及更高分数；这些数值是实验目标，不是效果保证。

同一个 user_id 在不同日期表示同一个匿名用户。长期偏好可能延续，但短期兴趣、看到的广告和展示环境会变化。用户 ID 有用，不等于只记住用户编号就足够。

广告点击监督比较稀疏：当前训练部分每个用户的广告点击次数中位数为 1，1,484 个用户没有正点击。因此不宜为每个用户单独训练一个大模型，应采用共享参数和受约束的个性化修正。

## 3. 当前基线与已有证据

以下结果均来自当前“每天约 80% 训练、20% 验证”的同一分组划分。

| 方案 | 训练 AUC | 验证 AUC | 训练—验证差距 |
| --- | --- | --- | --- |
| 逻辑回归，C=0.01 | 0.740960 | 0.719609 | 0.021351 |
| 逻辑回归，C=0.1 | 0.783569 | 0.723885 | 0.059684 |
| 共享模型＋统一组权重＋用户点击偏置 | 0.773355 | **0.730185** | 0.043170 |
| 再加入五组用户专属门控，较强约束 | 0.792004 | 0.729475 | 0.062529 |

当前推荐基线为 **user_bias**。相对此前验证最高的逻辑回归，验证 AUC 增加 **0.006300**；按用户成组的配对 bootstrap 95% 区间约为 **[0.004038, 0.009109]**。

这个区间来自已经用于选型的验证集，是探索性不确定性描述，不能替代独立复核。

已有结果支持：对用户整体点击倾向进行单独校正有价值。尚未支持：更复杂的用户组门控一定更好，或模型已经学会用户对具体兴趣类别的偏好。

当前最佳模型只使用广告标量字段，没有使用点击/关闭历史列表和逐条资讯行为。此前新写的原始资讯交叉注意力实验在不同日期上的收益不一致，不能将“再加注意力”当作尚未尝试过的必然提分方案。

## 4. 数据与验证约定

### 4.1 每一天都参与训练

- 在每个广告日期内按重复记录组抽出约 20% 验证，其余记录合并训练一个模型。
- 允许同一用户同时出现在训练和验证中，评估已有用户的新记录预测能力。
- 同一天原始输入相同的重复记录保持在同一侧；分组排除 label、log_id，并规范化无序列表。
- 原始文件实际包含 2019-11-10 至 2019-11-16。10 日只有 274 条记录，其单日指标不宜独立解释，但不因此删除该日期。

### 4.2 输入与标签边界

- 新增交互与行为表示从原始字段重新编码，不引入未经复核的旧统计缓存。
- 广告验证标签只用于评估，不进入用户画像、统计、预训练目标或特征构造。
- 词表、数值缩放及用户曝光置信度仅按相应训练范围拟合。
- 资讯作为作业提供的辅助数据使用；本方案的主设定允许查询广告当天及此前的资讯事件，属于离线同日快照设定。
- 资讯只有日级时间，不用 CSV 行号构造日内时间顺序。

### 4.3 复核方式

- 初筛固定当前划分，便于与 0.730185 配对比较。
- 候选通过后，再建立一个新的每日分组划分，重新训练完整方案。
- 新划分必须重新拟合预处理、共享模型、用户偏置和新增模块，不能只更换验证索引后沿用旧权重。
- 相同划分下的不同随机初始化不能代替不同划分的复核。
- 同日期留出 AUC 与整天留出的跨天 AUC 分开报告，不直接相减宣称提分。
- 最终用于预测 17 日时，可在设置确定后使用截至16日的全部有标签数据重训。每一天参与训练的正式流程保持不变。

## 5. 第一优先级：用户与具体广告的交互

### 要解决的问题

当前用户偏置主要表达“这个用户总体更容易点击”。它不能充分表达“同一个用户对 A 类广告偏好较高，对 B 类广告偏好较低”。

五组门控调整的是共享分数的组权重，也不直接等同于具体类别喜好。因此下一步优先增加明确的用户—广告交互。

### 实现方向

在当前基线的 logit 上增加小型低秩交互项，按以下顺序逐项比较：

1. 用户 × 应用类别。
2. 用户 × 推广应用。
3. 用户 × 广告位。
4. 有证据需要时，再加入用户 × 广告主。

示意：

```text
最终分数 = 当前基线分数
         + 用户向量 · 当前应用类别向量
         + 通过验证后才加入的其他交互项
点击概率 = sigmoid(最终分数)
```

当前基线已经包含用户点击偏置，新增模块不要重复叠加同一个偏置。

先使用 4 维和 8 维向量。仅“用户 × 20 个应用类别”的因子参数约为：

| 维度 | 因子参数量 |
| --- | --- |
| 4 | 34,304 |
| 8 | 68,608 |

这些仍然需要正则化。参数减少不等于自动消除过拟合。

### 初筛实验

| 编号 | 方案 | 要回答的问题 |
| --- | --- | --- |
| A0 | 当前 user_bias 基线 | 固定参照 |
| A1 | A0＋4维用户—类别交互 | 具体类别偏好是否有用 |
| A2 | A0＋8维用户—类别交互 | 增加维度是否真正改善验证 |
| A3 | 类别候选＋用户—应用交互 | 具体应用是否提供额外信息 |
| A4 | 已通过候选＋用户—广告位交互 | 展示位置偏好是否互补 |

后一个模块只有在前面的候选通过后才加入，避免一次改变多个因素。

约束与检查：

- 使用 L2、低维表示及训练曝光数量置信度约束个人项。
- 保留共享广告属性，避免完全依赖当前任务或素材 ID。
- 若采用冻结基线后的分阶段训练，训练修正模块时使用基线全链路的交叉拟合分数；不能只交叉拟合共享层，却把在本条标签上拟合过的个人偏置带回训练输入。
- 新分支做前向和梯度检查；低秩交互的两侧因子不能同时全零初始化而导致无法学习。

## 6. 第二优先级：原始点击与关闭历史的候选匹配

### 要解决的问题

同一个用户面对不同广告，应关注不同的历史。只对历史向量求平均，可能弱化某条与当前广告直接相关的记录。

### 直接使用的原始字段

| 原始字段 | 对应信息 | 当前候选字段 |
| --- | --- | --- |
| ad_click_list_v001 | 点击过的广告任务 | task_id |
| ad_click_list_v002 | 点击广告对应的广告主 | adv_prim_id |
| ad_click_list_v003 | 点击广告对应的推广应用 | spread_app_id |
| ad_close_list_v001 | 关闭过的广告任务 | task_id |
| ad_close_list_v002 | 关闭广告对应的广告主 | adv_prim_id |
| ad_close_list_v003 | 关闭广告对应的推广应用 | spread_app_id |

先比较完整原始列表的平均表示与候选条件化加权，点击和关闭分别建模。注意力查询由用户向量及当前广告属性共同产生，权重作用于该用户的历史项。

此方向借鉴 DIN 的候选相关历史加权思想；负反馈分支是本项目需要单独验证的设计，不能直接把论文收益当作本数据的收益。

必须保留：空历史回退、未知编号回退、正负反馈独立对照、原始列表长度检查。没有时间戳的列表不擅自增加精确时间顺序。

## 7. 第三优先级：增加资讯域监督

### 要解决的问题

原始资讯中有 87,034 次点击，可提供额外监督。直接把很多资讯字段输入广告模型，不一定能让稀疏的广告点击标签学好所有表示。

### 实验方向

1. 使用原始资讯数据训练资讯点击任务，学习共享用户和主题表示。
2. 将相关表示迁入广告模型，再用广告训练部分微调。
3. 比较从零训练、资讯预训练后微调，以及适度冻结表示这几种设置。
4. 如果单独预训练确有收益，再考虑联合任务及辅助损失权重。

避免同一任务的答案泄漏：

- 预测资讯点击时，不能把该条资讯的 label、阅读进度、点赞结果等点击后反馈同时当作输入。
- 阅读进度可作为另一个辅助目标，并使用合适的点击样本掩码。
- 对可能在点击后更新的兴趣快照，先核实定义并做字段消融。
- 记录用于表示训练与行为查询的资讯日期范围；跨天补充检查按相应时间边界重新构建。

先验证资讯监督是否能提升广告验证成绩，再增加辅助任务数量。

## 8. 统一验收与停止条件

### 每组必须保存

- 输入字段、原始文件哈希、训练与验证行索引及重复组定义。
- 参数数量、随机种子、正则强度、训练时间、停止位置。
- 同一最终检查点在完整训练集和验证集上的 AUC、Logloss。
- 验证预测、原始 log_id、模型文件及完整重载复算结果。
- 每日 AUC、样本数、正点击数；必要时附新广告和未见用户—广告组合结果。

### 候选推进标准

下列是工程筛选规则，不是统计显著性的通用定义：

1. 初筛优先推进相对 A0 增益至少约 0.002、或具有清楚互补价值的候选。
2. 同时检查训练—验证差距与 Logloss；不能因为训练 AUC 更高就判定更好，也不能仅追求差距为零。
3. 改善应分布在主要日期，不由10日等极小样本单日驱动。
4. 候选在新每日分组划分上重新训练后，增益方向应保持一致。
5. 比较差值的用户成组 bootstrap 区间，并注明选型与多次比较带来的偏差。
6. 最佳模型从保存文件重载，对完整验证集重新预测，概率误差满足记录的容差。

### 停止或回退

- 新模块只提高训练分数、验证退步：加强约束或回退。
- 增大维度、层数后验证不改善：保留较小版本。
- 门控与简单用户偏置相当：保留偏置，不把复杂度当作进步。
- 仅在一个反复使用的划分上提升：保留为探索性结果，不宣布稳定突破。
- 多个小改动连续无收益：重新检查输入信息、字段关系与数据边界，避免无限调参。

## 9. 推荐执行顺序

```text
锁定当前 0.730185 基线及每日划分
    ↓
4维 / 8维用户—应用类别交互
    ↓
逐项验证用户—应用、用户—广告位交互
    ↓
原始点击 / 关闭历史的候选匹配
    ↓
资讯监督预训练与迁移
    ↓
新划分复核及必要的未来日补充检查
    ↓
设置固定后，全部有标签数据重训并预测17日
```
